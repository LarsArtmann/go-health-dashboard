01Summary

templ-components is the dashboard's UI vocabulary, and the dashboard uses it the way the library wants to be used: every rendered surface — page shell (layout.Base with HTMX deliberately disabled), header (display.PageHeader), stat cards, alert banner, severity cards, service tables, badges, sparkline, collapse, empty state — is a library component, verified in a real browser under strict CSP (both themes, axe-audited). The datastar seam uses the pinned SDKScript/ LiveRegion/RetryAlways stack that fixed the stale-browser reconnect bug. The icons package eliminated every inline <svg>. What is missing is small and mostly not applicable: four component families (forms, navigation, charts, interaction overlays) serve apps this is not. One finding is real, easy, and already backed by an open TODO row.

03Findings

MISSED OPPORTUNITY · trivial effort

display.ListNote already solves the open timeline-cap TODO

TODO_LIST row “ListNote truncation notice for the 5-entry timeline cap” · view.templ timelineCard caps at maxTimelineEntries (5) and FEATURES calls the missing notice an honesty gap · the library ships the exact component: ListNote(ListNoteProps{Shown, Total}) renders “Showing N of M” and nothing when everything fits

The timeline silently drops entries past the fifth. The audit of this very repo logged the fix as a TODO row; the library component that implements it verbatim went unnoticed. One swap in timelineCard: replace the hand-rolled cap logic's silence with @display.ListNote(display.ListNoteProps{Shown: len(shown), Total: len(all)}). Impact: the honesty gap closes with library-tested markup instead of new hand-rolled copy.

JUSTIFIED NON-ADOPTION · documented

Hand-rolled client-side filter vs forms.FilterInput

view.templ groupRows — data-bind query signal + data-class:hidden rows, with the load-bearing :not(.hidden) mobile-specificity guard

forms.FilterInput is a debounced GET-form input (server round trip). The dashboard's filter is a client-side Datastar signal — no round trip, works across SSE patches, required for the embedded-SDK offline story. Different mechanics; the hand-rolled version is correct. Keep.

JUSTIFIED NON-ADOPTION · verified premise

groupCountBadge is not display.CountBadge

view.templ groupCountBadge renders a plain count chip in card headers

display.CountBadge is a notification OVERLAY (badge pinned to a child's top-right corner, hidden at 0, “Max+” beyond Max) — a different visual contract. The audit initially flagged this as duplication; reading the component contract refuted it. No action.

NOT APPLICABLE · 4 families

forms (20), navigation (11), charts (5), interaction overlays (~12)

A status page has no forms, no multi-page navigation, no line/pie/bar charts (the trend sparkline is the right tool), and no modals/drawers/tabs/carousels. Feedback's Toast/ProgressBar family becomes relevant only if async operations (e.g. export readiness) ever surface in the UI — noted, not recommended today. Combined with the 13 used components this accounts for the full 87-symbol surface; nothing else sits unused in an applicable category.
