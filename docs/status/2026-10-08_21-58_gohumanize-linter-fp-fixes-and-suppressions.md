## a) FULLY DONE

### 1. H009 detector bug — root-caused and fixed in go-humanize-linter

- **Finding:** `trend.go:178` (`ExportHandler`) flagged as "manual float-with-comma formatting".
- **Root cause (verified at source level):** `strconv.FormatFloat(v, 'g', -1, 64)` — source-level `-1` parses as `ast.UnaryExpr`, and `getBasicLit` (pattern_helpers.go:109-120) _strips the unary minus_, so precision `-1` reached the check as `"1"`. The `lit.Value != "-1"` exclusion was **dead code**. Combined with `b.WriteByte(',')` — which are RFC 4180 **CSV field delimiters**, not digit grouping — `hasCommafPattern` fired.
- **Why tests stayed green:** `TestHasFormatFloatPrecision` fed `&ast.BasicLit{Value: "-1"}` — an AST shape the Go parser can **never produce**. Impossible-input test pattern.
- **Fix (pattern_commaf.go):** new `signedIntLiteral` helper resolves sign before literal unwrapping (handles UnaryExpr SUB/ADD, parens, defensive leading-minus BasicLit); new `hasFixedFloatVerb` requires a literal `'f'` verb (mirrors the Sprintf path, which already rejects `%.Ng` via `walkFormatFloatVerbs`); `hasFormatFloatPrecision` rewritten on top of both.
- **Regression guards:** realistic-shape unit cases (unary `-1`, `-10`, paren-wrapped, `+2`, `'g'`/`'f'` verbs) + `h009_negative` fixture `csvSampleRow` mirroring the dashboard's ExportHandler verbatim. Proven: the stale binary (4cee06d) flags the new fixture at `main.go:44 [H009]`; the fixed code does not.

### 2. `--verify-suppressions` staleness false positive — root-caused and fixed

- **Discovery:** after adding working suppression directives to the dashboard, `--verify-suppressions` flagged **both as stale** ("suppresses zero findings").
- **Root cause:** `registry.Run` applies suppression _during detection_ (`checkFuncDecls` skips suppressed functions), so the report the CLI passed to `VerifySuppressions(dir, report)` was missing exactly the findings the directives suppressed. Report-based matching could therefore **never** validate a working directive. Confirmed against the linter's own `testdata/h001_suppressed` fixture — also flagged stale.
- **Why tests stayed green:** `TestVerifySuppressions_UsedSuppression` hand-fabricated a report ("Simulate a report that contains an H001 finding" — its own comment). Impossible-input test pattern, **second occurrence of the same class in one session**.
- **Fix (suppression.go):** `VerifySuppressions(dir)` and `VerifySuppressionsInFiles(fset, files)` now re-detect **unsuppressed** findings internally (`unsuppressedFindingsIndex` / `unsuppressedFindingsFromFiles` / `indexDetection` over `allRuleDetectors()`) and match directives against that. Bonus correctness: verdicts are rule-set independent (a directive stays valid when its rule is merely disabled). **Breaking library-API change** — report parameter removed from both functions.
- **Callers updated:** CLI (`appendSuppressionFindings`), plugin (`runDetector` — dropped the now-unneeded `NewReportFromFindings` construction), 5 suppression tests rewritten to be genuinely end-to-end, new CLI regression test `TestCLI_VerifySuppressions_UsedSuppressionNotFlagged` (exit 0 for a working directive).

### 3. Dashboard H003 sites — policy-compliant suppression

- `dashboard.go` `HealthCheck` watchdog: directive `//nolint:gohumanize // watchdog diagnostic needs millisecond precision; humanize.RelTime would coarsen it`. RelTime's coarse buckets would destroy the `6.002s ago, stale after 6s` diagnostic precision.
- `status.go` `formatAge`: directive `//nolint:gohumanize // coarse stamp is deliberate (anti-fingerprint, golden-pinned); humanize.Time renders finer ages`. Adopting humanize would _regress_ the documented accepted-risk decision (coarse display) and churn goldens.
- **Syntax gotcha discovered the hard way:** the linter's documented scoped form `//nolint:gohumanize:H003` is rejected by golangci's nolintlint ("should match `//nolint[:<comma-separated-linters>]`"), and wsl_v5 rejects a blank line between directive and statement. Final form: unscoped `//nolint:gohumanize`, hugging the statement. Zero-deps policy intact — no `dustin/go-humanize` added.

## e) WHAT WE SHOULD IMPROVE

1. **Impossible-input tests are a systemic linter-suite hole.** Both linter bugs shipped _with passing test suites_ because tests fabricated inputs (`BasicLit("-1")`; hand-built reports) the pipeline never produces. Rule of thumb going forward: verification/matching logic must be tested through the real entry point (CLI-on-fixture, plugin `analysistest`), with fabricated-input tests demoted to helper-level only.
2. **Scoped suppression syntax vs golangci nolintlint is an unresolved fleet-level conflict.** go-humanize-linter documents `//nolint:gohumanize:H003` as its standard; any repo co-running golangci with nolintlint (all of them, effectively) rejects that format. This session worked around it with the unscoped form; the linter should either bless the unscoped form for golangci-coexisting repos or the fleet's nolintlint configs need a documented exception.
3. **Generated-file freshness has no hard gate.** The templ bump shipped un-regenerated and nothing failed locally until an unrelated session ran a fresh build. A CI step that fails when `go tool templ generate` (or any pinned generator) produces a diff would have caught it at the bump commit.
4. **Gate discipline for me:** never stack a new gate on a possibly-running background command; always confirm background completion (job_output with wait) before dependent steps; never judge lint by empty output — capture exit codes.
5. **Stale-binary trust.** The fleet pattern repeated: installed tooling lags repo HEAD (erraudit precedent, now go-humanize-linter). `--version`-vs-HEAD checks should be a reflex before interpreting linter output.
6. **Daemon commit granularity.** Meaningful multi-part work (linter fix + dashboard directives + templ regen + docs) landed as seven message-less auto-commits across two repos, plus one mixed with a foreign `flake.nix` edit. The fleet discipline ("commit intent-bearing changes immediately") exists precisely for this; my commit hard-rule conflicts with it and produced garbage history that will need folding before any release.
