## Context

The feedback document identified 7 architectural mistakes in the v1 implementation:

1. Designed prerequisite work for code that already existed in go-health
2. Made HTMX polling the default, SSE optional
3. Used content negotiation when separate routes are simpler
4. Used deprecated API types (`AlertType` instead of `FeedbackType`)
5. Designed a two-mode architecture (polling + SSE) that doubled everything
6. Elevated internal details (broadcaster) to architecture decisions
7. Didn't verify composability before planning integration

This session rewrote the entire package to fix all 7 issues.

---

## A) FULLY DONE

### Architecture: SSE-first, Datastar-powered, single-mode

- **SSE is the only mode** — No `RefreshMode` type, no polling, no `WithRefreshMode`. One template, one SSE endpoint, one test surface. Fix for mistake #2 and #5.
- **Separate routes, no content negotiation** — `/health` is HTML-only (browser), `/readyz` is JSON-only (kubelet). No `Accept` header parsing. Fix for mistake #3.
- **Dashboard is a pure consumer of go-health** — Zero changes to go-health needed. `CachedResponse()`, `RefreshInterval()`, all handler methods already exist. Fix for mistake #1 and #7.
- **Broadcaster is an internal detail** — Not mentioned in public API docs or architecture decisions. Just an implementation detail of `pusher.go`. Fix for mistake #6.

### `status.go` — View model layer

- `mapStatusToBadge` — pass→BadgeSuccess, warn→BadgeWarning, fail→BadgeError
- `mapStatusToFeedback` — pass→FeedbackSuccess, warn→FeedbackWarning, fail→FeedbackError (canonical types, not deprecated `AlertType`). Fix for mistake #4.
- `mapStatusToText` — human-readable status strings
- `viewModel` struct: Title, Status, FeedbackType, StatusText, Version, Uptime, LatencyMs, Groups, SSEURL, DatastarNonce, TailwindNonce
- `buildViewModel` — assembles full view model with shutdown overlay
- `groupChecks` — partitions by severity, sorted alphabetically
- `rowsToTableRows` — converts to templ-components TableRow with Badge components
- `fingerprintChecks` — deterministic change detection (sorted keys). Fix for the critical `hashChecks` bug from previous session.

### `routes.go` — Route definitions

- `Routes` struct: Dashboard, SSE, Liveness, Readiness, Startup (no Partial — removed)
- `DefaultRoutes()` returns `/health`, `/health/sse`, `/healthz`, `/readyz`, `/startupz`

### `dashboard.go` — Public API

- `Version = "0.1.0"` constant
- `Config` struct: Title, PushInterval, PushMode, Routes, Nonce
- `Option` type + `WithTitle`, `WithPushInterval`, `WithPushMode`, `WithNonce`, `WithRoutes`
- `Dashboard` struct with `probe`, `cfg`, `push` fields
- `New(probe, opts...)` with defaults (Title="Health Dashboard", PushMode=PushOnChange, Routes=DefaultRoutes())
- `resolvePushInterval` — falls back to probe interval, then 2s default
- `Handler()` — renders HTML dashboard page
- `SSEHandler()` — SSE endpoint handler
- `RegisterRoutes` — wires dashboard + SSE + probe endpoints
- `Start(ctx)` — launches SSE pusher goroutine
- `Shutdown()` — closes broadcaster

### `pusher.go` — SSE pusher (new file, replaces old `realtime.go`)

- `PushMode` type: `PushOnChange`, `PushAlways`
- `pusher` struct: broadcaster, dashboard, interval, pushMode, mutex, lastStatus, lastFingerprint
- `newPusher(d)` constructor
- `start(ctx)` goroutine — ticks at interval, broadcasts, closes on ctx done
- `broadcast()` — reads cache, checks shouldBroadcast, renders patch, broadcasts
- `renderPatch(resp)` — renders `dashboardContent` via `datastar.ElementsFromTempl` with `WithModeInner()` + `WithSelectorID("health-region")`
- `shouldBroadcast(resp)` — deterministic change detection via `fingerprintChecks`
- `sseHandler` — SSE endpoint with heartbeat, initial state push, subscriber forwarding
- Uses go-datastar `ElementsFromTempl` (NOT vanilla EventSource). go-datastar is a real dependency now.

### `view.templ` — Full dashboard page

- Uses `layout.Base` with `HTMXVersion: ""` (disables HTMX injection entirely)
- `datastar.SDKScript` loaded in head (Datastar v1.0.2 from CDN)
- `datastar.LiveRegion` wraps health content with `AutoStart: true` and `LivePolite`

- `dashboardContent` — shared inner content: Alert banner + severity-grouped Cards with Tables
- 3 StatCards: Version, Uptime, Check Latency
- `view_templ.go` generated by `templ generate`

### G1: What license should this project use?

The LICENSE file says **PROPRIETARY** (all rights reserved, contact for licensing). The README (written this session and the previous one) says **MIT**. These contradict each other. I should have read the existing LICENSE before writing "MIT" in the README. Which license do you want?

### G2: Should the replace directives in go.mod stay or go?

`go.mod` has 6 replace directives pointing to local sibling repos (`../go-health`, `../templ-components`, `../go-datastar`, `../go-sse`, `../go-error-family`, `../go-branded-id`). These are required for local development but prevent `go get` from working for external consumers. Should they stay (local-dev-only, document loudly) or should upstream repos be tagged first?

### G3: Is the GOEXPERIMENT=jsonv2 requirement acceptable for consumers?

Every `go build`, `go test`, `go run` for this package (and all transitive consumers) requires `GOEXPERIMENT=jsonv2` because go-sse imports `encoding/json/v2`. This is an experimental Go feature. Options:

- Accept it (current approach — document loudly, set in flake.nix)
- Fork go-sse to remove json/v2 (maintenance burden)
- Build-tag gate the SSE code (complex, two code paths)
- Wait for Go 1.27 where json/v2 may be stable
