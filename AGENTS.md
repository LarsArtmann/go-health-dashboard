# AGENTS.md — go-health-dashboard

Browser-friendly health dashboard composition layer between [go-health](https://github.com/larsartmann/go-health) (health-checking SDK) and [templ-components](https://github.com/larsartmann/templ-components) (UI rendering). HTTP content negotiation: JSON delegates to go-health handlers; HTML renders a rich browser dashboard.

**Module**: `github.com/larsartmann/go-health-dashboard` · **Package**: `dashboard` · **Go**: 1.26.5 · **Status**: v0.1.0 (alpha)

## Architecture

Single-package library (`dashboard`) with these source files:

```
doc.go           — Package doc comment (quick start, content negotiation rationale)
types/status.go  — Status mapping (health.Status → BadgeType, AlertType, text), viewModel, checkRow, groupChecks, rowsToTableRows
dashboard.go     — Dashboard struct, Config, Option type, New(), WithTitle/WithRefreshInterval/WithRefreshMode/WithRoutes/WithSSEPush, Handler(), PartialHandler(), SSEHandler(), RegisterRoutes(), Start(), Shutdown()
routes.go        — Routes struct, DefaultRoutes()
handlers.go      — contentNegotiationHandler, partialHandler, renderHTML, buildData, acceptsHTML
realtime.go      — ssePusher struct, PushMode enum, start goroutine, broadcast, shouldBroadcast (change detection), sseConnectionHandler, hashChecks
view.templ       — View (full page), dashboardPolledRegion, dashboardContent, tailwindScript
partial.templ    — Partial (HTMX polling fragment)
view_templ.go    — Generated by templ generate
partial_templ.go — Generated by templ generate
```

### Key Design Decisions

- **Content negotiation via Accept header** — The dashboard lives at `/health` (same path as readiness). `text/html` renders the dashboard; `application/json` delegates to probe.ReadinessHandler(). `*/*` defaults to HTML (browsers); missing Accept defaults to JSON (kubelet).
- **Status mapping: direct constants** — go-health uses `pass`/`warn`/`fail`. templ-components' StatusBadge string map doesn't recognize these. We map directly to `BadgeType` constants (`BadgeSuccess`, `BadgeWarning`, `BadgeError`) — type-safe, no cross-library changes.
- **HTMX polling as default, SSE as opt-in** — Polling reads the atomic cache pointer (zero dependency calls per poll). SSE adds connection lifecycle complexity. Available via `WithRefreshMode(RefreshModeSSE)`.
- **Partial template for polling** — The polling endpoint returns the PolledRegion wrapper + fresh content (outerHTML self-replacing pattern). The PolledRegion's hx attributes survive the swap.
- **CachedResponse for zero-cost polling** — Dashboard reads `probe.CachedResponse()` which reads the atomic `p.latest` pointer. Lock-free, zero dependency calls per poll.
- **StatCards + Card grouping** — Version/Uptime/Latency shown as StatCards. Checks grouped by severity: Critical Failures, Non-Critical Issues, Healthy Services. Each group in a Card with a flush Table.
- **SSE status change detection** — Default `PushOnChange` mode only broadcasts when overall status or individual check results change. `PushAlways` sends on every tick.
- **GOEXPERIMENT=jsonv2 required** — The go-sse dependency imports `encoding/json/v2` (Go 1.26 experimental). All Go commands must set `GOEXPERIMENT=jsonv2`.

### Data Flow

1. User creates `Dashboard` via `New(probe, opts...)` — options write to a `Config` struct
2. `RegisterRoutes(mux, routes)` wires dashboard + partial + probe endpoints
3. Browser GETs `/health` with `Accept: text/html` → `View(viewModel).Render(ctx, w)`
4. HTMX polls `/health/partial` every N seconds → `Partial(viewModel).Render(ctx, w)`
5. Both paths read `probe.CachedResponse()` — lock-free cache reads

### SSE Mode Data Flow

1. `Start(ctx)` launches the `ssePusher` goroutine
2. Pusher ticks at `RefreshInterval`, reads `CachedResponse()`, renders `dashboardContent`
3. Pusher broadcasts SSE events via `sse.Broadcaster`
4. SSE clients connect to `/health/sse`, subscribe to broadcaster, receive `update` events
5. Client-side `EventSource` replaces `#health-region` innerHTML

## Gotchas

- **GOEXPERIMENT=jsonv2 is required** — The go-sse dependency uses `encoding/json/v2`. Set `GOEXPERIMENT=jsonv2` for all Go commands. The flake.nix devShell does this automatically.
- **templ generate before build** — `*_templ.go` files are committed but `templ generate` must run to ensure they match `.templ` sources. The flake.nix runs `templ generate` as a pre-build step.
- **Probe must be Started** — Call `probe.Start(ctx)` before serving traffic so the cache is populated. Without Start, `CachedResponse()` returns a zero-value Response (empty checks).
- **PolledRegion uses outerHTML swap** — The partial endpoint returns the PolledRegion wrapper + fresh content. HTMX replaces the entire div, keeping hx attributes alive for the next poll cycle.
- **Replace directives for local dev** — go.mod has `replace` directives pointing to sibling repos. Remove before publishing or when upstream repos are tagged on GitHub.
- **go.work in parent directory** — `~/projects/go.work` includes all LarsArtmann Go repos. The flake.nix sets `GOWORK=off` implicitly (no GOWORK setting means it uses the default, which finds go.work up the tree).

## Dependency Notes

### go-health (`github.com/larsartmann/go-health`)

Provides `Probe`, `Response`, `Check`, `Status`. Two accessors were added for this package:

- `Probe.CachedResponse() Response` — reads atomic cache, overlays shutdown flag
- `Probe.RefreshInterval() time.Duration` — returns configured refresh interval

### templ-components (`github.com/larsartmann/templ-components`)

Provides `display` (Card, Table, Badge, StatCard, Grid), `feedback` (Alert), `htmx` (PolledRegion), `layout` (Base, Container). All components accept children via `{ children... }` in templ.

### go-sse (`github.com/larsartmann/go-sse`)

Provides `Broadcaster[sse.Event]` (fan-out hub) and `Stream` (single SSE connection). Required for SSE push mode. Imports `encoding/json/v2` which requires `GOEXPERIMENT=jsonv2`.
